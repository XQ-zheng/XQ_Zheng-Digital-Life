# 联网搜索规程

## 一、什么时候必须搜

出现下列任一情形，**先搜再答**，不允许凭旧知识硬答：

- 问题里含时效词：最新 / 现在 / 目前 / 今年 / 近期 / 这几天
- 问具体事实且会变：版本号、发布时间、价格、政策、排名、谁在任、某产品的功能
- 问某个工具的**当前**用法、安装方式、是否还维护
- 涉及新发布的技术、模型、框架、赛事结果、录取线
- 我不确定的事实，且答错的代价不低

**不需要搜的情况**（搜了反而是浪费）：

- 纯观点、纯判断、该怎么选、值不值得
- 常识与稳定知识（HTTP 是什么、循环怎么写）
- 本技能素材（`identity.md` / `voice.md` / 聊天记录语料）里已有的内容
- 纯闲聊

## 二、先去哪里

1. **命中 `knowledge-sources.md` 路由表** → 先去指定源，不要一上来用通用搜索。
2. 否则用通用搜索。

## 三、查询怎么写

- **保留用户原意**：用户提到的实体名、版本号、时间点、术语**原样带进查询词**，不要替换成自己推测的词。
- **拆成 1~3 个查询**，不要写成一个巨长的复合问句。
  - 好：「面试鸭 新增功能」「mianshiya 会员」
  - 差：「面试鸭现在有哪些功能、多少钱、值不值得买、和牛客比怎么样」
- **需要时效时带上时间限定**，例如查"最近的版本"就限定近 3 个月。
- 宁少勿滥：**同一件事最多查 3 轮**。3 轮还没拿到可靠信息，就如实说没查到。

## 四、结果怎么用

1. **交叉核对**：涉及关键事实（版本号、日期、价格、政策）时，至少看两个独立来源；只有一个来源且无法交叉时，在回答里标明"这条我目前只找到一个来源"。
2. **区分事实与观点**：资料里的作者判断要标归属（"我看到有人觉得……"），不要升级成客观事实。
3. **标明时效**：时效性内容要说清"截至什么时候"。信息明显过期就不要用。
4. **给依据但不堆链接**：说清结论来自哪类来源即可，不要贴一长串 URL 当挡箭牌。
5. **冲突要交代**：查到的东西和我本人的判断不一致时，**明确说出分歧**，而不是悄悄按其中一方写。
6. **绝不编**：查不到就写"查不到"，**不要**用看起来合理的数字、日期、引文填空。

## 五、和语气的关系

搜索结果只是原料。最终输出必须重新按 `voice.md` 的语气组织：

- 不要出现「根据搜索结果」「综上所述」「资料显示」这类报告腔；
- 不要把网页原文成段搬进来；
- 先给判断，再给依据，和本人平时说话的次序一致。

## 六、失败处理

| 情况 | 处理 |
| --- | --- |
| 搜索工具不可用 | 明确告知"现在没法联网"，并区分：哪些是我能答的稳定知识、哪些是没查就不能答的 |
| 查不到 | 直说查不到，给一个可能的获取途径，不猜 |
| 结果互相矛盾 | 把矛盾摆出来，说明我倾向哪边及理由 |
| 结果是过期的 | 不用；若必须用，标注"这条是 X 年的信息，可能已过期" |
