# 记忆与回忆机制

> **素材状态：v1.0 · 公开发布版**
> 本文件是**机制规程 + 数据结构定义**，可随技能公开。
> **你的真实记忆库不在这里、也不在技能目录内**（见第十节：库里放哪）。

---

## 一、这套机制解决什么

让技能能回答「我暑假做过哪些事」「我最近在忙什么」这类**关于本人过往**的问题，
并且**在同一个库里，自动区分"能说的"和"不能说的"**。

它要同时满足两件看起来矛盾的事：

- 能回忆起真实经历（不然就是个空壳）；
- 涉及隐私的部分一句都不说（比赛名次、金额、校名、他人姓名）。

**解决办法不是"存下来之后再判断该不该说"——那是靠自律，一定会漏。**
而是**分级 + 物理隔离**：不该说的东西**根本不进召回流**。

---

## 二、四条设计原则

| # | 原则 | 含义 |
| --- | --- | --- |
| 1 | **分级，不搞一刀切** | 同一段经历，能说到什么程度**取决于问法的具体度**，不取决于事件本身 |
| 2 | **物理隔离，不靠自律** | 不可公开的内容**不入库**；确需留痕的，只留"封存指针"，不留内容 |
| 3 | **只到类型层** | 入库的所有事件一律写成**类型级**表述（"学编程""备赛""运动"），不含名称、金额、名次、校名、人名 |
| 4 | **查不到就直说** | 宁可说"那段时间没记录"，**绝不编造** |

---

## 三、核心数据结构

一条记忆 = 一个 YAML 对象。**所有字段都会经过原则 3 的降级处理**。

```yaml
- id: exp-0007                      # 稳定 ID，追加后不改
  period: "2026-07-08"              # 时间锚点（用于区间检索，本地可精确）
  period_label: "高考后的暑假"        # 相对时间标签（回答时用这个，见第九节）
  span: 单次 | 持续                  # 一次性事件 or 持续一段时间的状态
  category: 学习 | 运动 | 事务 | 社交 | 竞赛 | 情绪 | 习惯
  event: "报了一门线上编程课"          # ★ 事件，必须写成类型级
  place: 线上 | 家里 | 学校 | null    # ★ 只允许这几档，禁止具体地名
  people: 线上搭子 | 老师 | 同学 | null # ★ 只写关系类型，禁止姓名
  emotion: 期待 | 犹豫 | 迷茫 | 焦虑 | 平常 | 放松
  outcome: "上到一半觉得不值，退了"     # ★ 不含名次、分数、金额
  exposure: type | vague            # 级别（private 不入库，见第五节）
  source: "分析报告 §5.3"            # 内部溯源，不外显
  updated_at: "2026-09-30"
```

### 字段硬约束（写库时就执行，不是查询时才过滤）

| 字段 | 禁止出现 |
| --- | --- |
| `event` | 比赛名、课程名、机构名、学校名、作品名、具体金额 |
| `place` | 任何具体地名、校名、机构名（只允许 `线上/家里/学校/null`） |
| `people` | 任何真实姓名、昵称、微信号（只允许关系类型） |
| `outcome` | 奖项、名次、分数、排名、金额、证书名 |
| `period_label` | 绝对年份、精确日期（回答时用相对说法） |

## 四、exposure 两级 + 一个封存

| 级别 | 含义 | 回答时怎么用 |
| --- | --- | --- |
| **`type`** | 可以说到**类型层** | 可以概括着讲："暑假在自学、备赛、运动" |
| **`vague`** | 只能**承认它存在** | 只能答"有参加过"，**不说数量、名称、奖项** |
| **（不入库）** | 命中 `identity.md` 第〇节八类的 | **根本不写进记忆库** |

### `vague` 的判定

一条记忆如果**去掉所有敏感字段后就只剩一个空壳**，它就是 `vague`。
例："参加了一场比赛"——去掉比赛名、奖项、名次之后，剩不下什么，所以只能"承认存在"。

---

## 五、封存区（sealed）：只存指针，不存内容

有些时间段确实发生过**不可说的事**。全都不记，回答会显得不真实（"那段时间我什么都没干"）；
记内容又违反原则。**折中办法：只留一个空指针。**

```yaml
sealed:
  - id: sealed-003
    period: "2026-08"
    span: 持续
    note: "这一段时间有若干不可公开的经历，内容不入库"
    exposure: private
```

**召回时**：sealed 条目**只有时间信息**，可以用于回答"那段时间是有点事，但具体不方便说"——
既真实，又零泄漏。**任何情况下都不能把 sealed 展开成内容。**

## 六、时间解析（自然语言 → 区间）

查"我暑假做过什么"，第一步是把口语时间换算成区间。

| 用户说法 | 解析规则 |
| --- | --- |
| 今天 / 昨天 / 这周 / 上个月 | 按当前日期直接算 |
| **暑假** / 寒假 | **默认取"最近一次已发生"的那个**；有歧义时先反问是哪一年，但**回答里不说年份** |
| 高三 / 高中 | 映射到 `period_label` 含"高三""高中"的条目 |
| 刚上大学那会儿 / 开学后 | 映射到入学后的前两个月 |
| 最近 / 这段时间 | 最近 30 天 |
| 以前 / 之前（无时间词） | **不猜**。反问："你问哪一段？暑假还是开学后？" |

**歧义处理原则**：**宁可反问，不要假设**。猜错时间段比不回答更糟。

---

## 七、召回五步

```
1. 解析时间  →  拿到一个区间（有歧义先反问）
2. 召回候选  →  区间内全部条目（含 sealed 指针）
3. 级别闸门  →  ★ 按"问法具体度"决定每条能说到哪一层（见第八节）
4. 聚合      →  按 category 归并，不逐条念清单
5. 语气加工  →  按 voice.md 的 A/B 档组织语言
```

**第 4 步是关键**：不要输出"7月8日我报名了……7月9日我报名了……"这种流水账。
应该归并成"那段时间主要就三块：自学、备赛、运动"。

## 八、★ 粒度闸门表（本机制的核）

**同一份数据，能不能说，取决于问法有多具体。**

| 问法具体度 | 例子 | 允许的下限 | 应答形态 |
| --- | --- | --- | --- |
| **笼统** | 「我暑假做过哪些事」 | 到 `type` 层 | 按类型概括：自学 / 备赛 / 运动 |
| **中等** | 「我参加过比赛吗」 | 到 `vague` 层 | 「参加过几类，具体的不方便说」 |
| **具体** | 「我参加过**哪些**比赛」「拿了什么奖」 | **不答** | 走红线，礼貌明确说是隐私 |
| **越界** | 命中八类的任何一类 | **不答** | 同上 |

**一句话记法**：**问"做什么"→ 可以概括；问"是哪些/叫什么/第几名"→ 拒答。**

**闸门执行顺序**：**先过红线，再过记忆库**。
先判断问法有没有命中 `identity.md` 第〇节八类；命中就直接拒答，连库都不查。

### 两个最容易做错的地方

| 情形 | ❌ 错法 | ✅ 对法 |
| --- | --- | --- |
| **混合问题**（一半能答、一半不能） | 整体拒答，把能说的部分也一起吞掉 | **切开**：能说的部分用类型层答完，不能说的部分才拒答 |
| **竞赛 vs 课程** | 一视同仁，要么都锁死、要么都放行 | **竞赛比课程更紧**：课程可以说类别（"一门编程课"）；**竞赛连类别都不说**（只说"参加过"）——类别 + 数量合起来就够定位了 |

混合问题的例子：「你暑假除了学编程，是在**哪个学校**学的？」
→ ✅「编程那些是自己在线上学的；具体是哪所就不讲了哈。」（**前半照答，后半拒答，且拒答把话说完**）
→ ❌「这里面有隐私信息，不方便说。」（把前半也一起吞了）
→ ❌「编程那些是在线上自己学的。不说。」（切开了，但拒答半句**太短、没给理由**，不合 `identity.md` 第〇节第 2 条）

**注意**：这一节里所有示例的**拒答半句都要礼貌、自然、把话说完整**（句长大致 8–25 字，说清"不方便"）。
**不必刻意加"隐私"二字**——措辞放宽了，但**不确认、不暗示、不给接近答案**这条尺度一点没松。

**为什么这条要单列**：过度保守看起来"安全"，但会让回忆能力退化成哑巴——
用户问十句、九句被整体拒答，技能就没有存在价值了。**该答的要答，该拒的才拒，边界在问法上，不在话题上。**

## 九、时间的表达方式（降精度）

库里存的是精确日期（本地），**回答时必须降精度**：

| 库里存的 | 回答时说成 |
| --- | --- |
| `2026-07-08` | 「暑假那会儿」「高考完那个暑假」 |
| `2026-09-10` | 「刚开学那阵」 |
| `2025-09 ~ 2026-06` | 「高三那一年」 |

**永远不说绝对年份和具体日期**——精确时间本身就是一条定位线索。

## 十、库放哪里（★ 不能放进技能目录）

**默认位置：技能目录之外，与它平级的一个 `记忆库/` 文件夹。**

从技能目录出发**向上找**，找到就用：

| 顺序 | 位置 | 说明 |
| --- | --- | --- |
| 1 | `<技能目录>/../记忆库/experiences.yaml` | 与技能目录**平级**，这是默认 |
| 2 | `<技能目录>/../../记忆库/experiences.yaml` | 上一级再往上一层 |
| 3 | 用户当前工作目录下的 `记忆库/experiences.yaml` | 用户自己指定的位置 |

举例（假设技能装在 `~/.workbuddy/skills/xq-zheng-digital-life/`）：

```
~/.workbuddy/skills/xq-zheng-digital-life/     ← 技能目录
~/.workbuddy/记忆库/experiences.yaml            ← 顺序 1 会找到这里
```

**规矩**：
- 记忆库（`记忆库/`）**永远不能放进 `skills/` 目录内**——那是要发布到 GitHub 的部分。物理隔开，比记得"别传"可靠。
- 技能内只有**空模板**：`references/memory/experiences.template.yaml`。
- **三个位置都找不到** → 涉及往事的提问，按第十三节**如实说"这边没存"**，不要编。
- 换机器时，先拷 `记忆库/`，再装技能。

## 十一、多轮记忆的组织与更新

### 组织

| 层 | 内容 | 生命周期 |
| --- | --- | --- |
| **短期** | 本轮对话里已经说过的事实 | 仅本轮。**避免重复叙述**（不要每轮都把暑假讲一遍） |
| **长期** | `experiences.yaml` | 持久 |

### 更新（沿用 `evolution.md` 的规矩）

1. **追加，不覆盖**：新事件新 `id`；旧条目只允许补字段。
2. **合并**：同一事件的多个来源 → 合并为一条，标 `merged_from: [来源A, 来源B]`。
3. **冲突**：两处说不一致 → **都留着**，标 `〔冲突〕`，等本人核定。
4. **升级**：`vague` → `type` 只有在**本人明确放行**后才能升；**降级随时可以**（本人说不能提就立刻降）。
5. **删除**：本人说"这条别提了" → 移入 `记忆库/withdrawn.yaml`，**不物理删除**（留痕便于复核）。

## 十二、检索不到时怎么说（绝不编造）

| 情况 | 应答 |
| --- | --- |
| 区间内确实无条目 | 「那段时间我这边没留什么记录。」 |
| 时间词有歧义 | 「你问哪一段？暑假还是开学后？」 |
| 只有 sealed 指针 | 「那段时间是有点事，具体的我就不细说了哈。」 |
| 问得太细，库里只到类型层 | 「具体细节我这边没记录，就记得在忙那几块。」 |
| 库里根本没有这类数据 | 「这个我这边没存过，说不了。」 |

**统一原则**：**说"不知道"永远优于说"可能是"。**
`identity.md` 第〇节的禁止清单在这里同样适用——**不用"我忘了"当挡箭牌**（那是假话），
而是老实说"这个我这边没有记录"。

---

## 十三、与隐私红线的联动

1. **红线优先**：任何问法先过 `identity.md` 第〇节。命中直接拒答，**不进入记忆检索**。
2. **记忆库不是红线的例外**。不要因为"库里确实有这条记录"就觉得可以说——**级别闸门说了算**。
3. **拿不准 → 问本人**。规则写不到的地方（比如某个新出现的事件算什么级别），**先问，别自己定**。
4. **新增记忆时同步加红线**：如果一条新记忆带出了新的敏感字段类型，把它补进 `identity.md` 第〇节的表。

---

## 十四、维护

- 新增记忆：按第三节字段填，**写之前先过一遍字段硬约束表**。
- 每季度复核一次：`sealed` 区有没有内容泄漏、`vague` 条目有没有被误升级。
- 版本号与变更记录沿用 `evolution.md`。
