# 个人蒸馏数字化模拟实体 · XQ_Zheng 的数字生命

`xq-zheng-digital-life` —— 把一个人在日常对话与书面表达里显现的**身份、判断框架、说话习惯**，
蒸馏成一个可以直接调用的技能：**读起来要像他本人在回答，而不是一份"关于他的分析报告"。**

> **一句话**：这是一个**语言风格与判断方式的模拟器**，不是本人，**也不具备任何身份效力**。
>
> ✅ **没有任何使用门槛。** 下载后把技能目录放进 skills 目录，即可直接开始对话——
> 不需要口令、不需要验证、不需要申请。

---

## 一、项目作用与适用对象

**项目作用**

把「一个人怎么说话、怎么看问题、怎么取舍」蒸馏成一套**可执行的规则**，
让模型在回答时能**用这个人的口吻和框架**说话，而不是用通用助手的口吻。

**适用对象**

| 对象 | 适用 | 说明 |
| --- | --- | --- |
| 想给自己的表达方式做一次蒸馏的人 | ✅ | 目录结构、规则组织方式、测试方法都可直接当模板复用 |
| 想研究"人格蒸馏怎么做"的人 | ✅ | 六源路由、档位判定、粒度闸门、隐私红线都写成了可照做的规则 |
| 想用它当写作风格参考的人 | ✅ | 拿来对照自己的用词与句式 |
| 想拿它冒充某人对外发言的人 | ❌ | **禁止代拟对外内容、禁止以他人身份对现实世界作出承诺** |
| 想看聊天原文的人 | ❌ | 技能**不含任何聊天原文**，只有归纳出的规则与实测统计 |
| 想套取隐私的人 | ❌ | 姓名、年龄、地域、学校与学业细节、联系方式一律拒答，**无例外** |

> ⚠️ **一句话定性**：这是一个**语言风格模拟器**，**不是任何人本人**。

## 二、主要功能

| 功能 | 能力 |
| --- | --- |
| **像本人一样说话** | 按 `references/voice.md` 的**两档**组织语言：即时对话用短句档（6–20 字、成串发），需要讲清楚时用长文档（一条、内部换行分段） |
| **按本人的判断框架作答** | 按 `references/identity.md` 的心智模型做取舍——先给判断再给依据，会算成本、会问"你图什么" |
| **联网核对最新信息** | 遇到"最新""现在""目前"这类时效问题**先查再说**，规程见 `references/web-search.md` |
| **按指定信息源路由** | 六源路由决策表见 `references/knowledge-sources.md` |
| **长期记忆与回忆** | 被问"以前做过什么"时按 `references/memory.md` 检索；**只说到类型层**，涉及名称/奖项/金额一律拒答；查不到就说没记录，绝不编 |
| **持续进化** | 新素材按 `references/evolution.md` **增量合并**，不重写整套 |
| **隐私保护** | 不回答姓名与年龄、地域、学校与学业细节、联系方式与他人信息、身体状况、账号与凭证、生物特征、财务数据（共八类）；**没有任何例外**。规则见 `references/identity.md` 第〇节 |

## 四、使用方法

**4.1 直接开始用（无任何校验）**

装好之后，新开一次对话，直接说：

> 使用 `$xq-zheng-digital-life`，以本人口吻回答：`<你的问题>`

也可以不说调用名——以下说法会自动触发：**「用我的口吻回答」「数字生命」「数字分身」「像我本人一样回答」「蒸馏我的表达风格」**。

**4.2 它会先判断问题类型**

| 类型 | 走法 |
| --- | --- |
| **隐私类** | 直接拒答，不查、不答、不解释 |
| **回忆类** | 先过红线，再过记忆库；只说到类型层 |
| **事实时效型** | 先联网查证，再答 |
| **专业领域型** | 先路由到指定信息源，再按本人语气加工 |
| **观点 / 判断型** | 用 `identity.md` 的心智模型推演 |
| **闲聊 / 情绪型** | 直接用 `voice.md` 的短句档回，不查、不说教 |

**4.3 想让它更像你**

技能的准确性取决于**投喂的素材**。要把它变成"你的"数字生命，按 `references/evolution.md` 补素材即可：
把新的自我描述、新的表达样本、新的判断结论并进去，**增量合并、保留旧结论对照**。

## 五、输入输出示例

> ⚠️ 下表的输出是按规则**现场生成的演示**，**不是任何一句真实聊天原话**。

| 典型输入 | 对应输出形态 | 走的规则 |
| --- | --- | --- |
| `在吗` | 一句短回应（6–20 字，句末不加标点，可挂 0–1 个表情码） | A 档 · 闲聊 |
| 「今天计划没做完，有点烦」 | 成串短句接住情绪，**不写成小作文** | A 档 · 情绪词不升级档位 |
| 「我该不该报这个班」 | 一条 150–250 字、内部换行分段、给判断也给依据 | B 档 · 求方案 |
| 「Python 现在最该学什么」 | 先查指定信息源 → 再按本人框架取舍 → 按语气组织 | 专业领域型 + 时效型 |
| 「你学校叫什么」 | 委婉拒答，说清"不方便"，**不列举、不给模糊答案** | 隐私红线 · 无例外 |
| 「你暑假都干了什么」 | 只说到类型层（"自学、备赛、运动这几块"），**时间降精度** | 回忆类 · 粒度闸门 |
| 「我以前是不是跟你说过 X」 | 检索不到就直说没记录，**绝不编一段往事** | 回忆类 · 不编造 |

## 七、怎么把项目弄到本地（三种方式的区别）

新手最容易在这里卡住。三种方式**不是版本不同，而是"拿到手的东西"不同**：

| | 点 **Download ZIP** | `git clone` | **Fork** |
| --- | --- | --- | --- |
| **本质** | 下载一个**压缩快照** | 把仓库**完整复制**到本地，**带 git 记录** | 把仓库**复制一份到你自己账号下** |
| **需要 git 吗** | 不需要 | 需要 | 不需要（网页上点一下） |
| **能看到源码** | ✅ | ✅ | ✅ |
| **能改** | ✅（改的是你本地的副本） | ✅ | ✅ |
| **以后能一键更新** | ❌ 只能重新下一份 | ✅ `git fetch` / `git pull` | ✅ 「Sync fork」 |
| **能向原项目提改动** | ❌ | ✅ 但需要写权限 | ✅ **这才是 fork 的用途** |
| **适合谁** | 只想看看 / 临时用一下 | 要长期用、要跟着更新 | 想改完**回馈给原项目** |

- **ZIP**：适合"我就想看看里面写了什么"。解压出来就是一个文件夹，缺点是没有 git 记录、**永远无法更新**。
  > 💡 **两个 zip 入口别搞混**：仓库首页绿色 **「Code → Download ZIP」** 给的是**当前最新代码**的快照；
  > 右侧 **Releases** 里的 `Source code (zip)` 给的是**某个已发布版本**的快照（打标签那一刻，之后不再变）。
  > 两者都没有 git 记录、都不能更新、都不能提合并请求。
- **clone**：适合"我要长期用"。终端里一句 `git clone 地址` 就下来了，以后 `git pull` 就能跟上更新。
- **Fork**：适合"我想改，而且希望原作者采纳"。**fork 出来的那份是你自己的仓库**，你在上面怎么改都不影响原项目；
  改完再发起一个 **Pull Request**（合并请求），请原项目把它并进去。

> **一句话区分**：**看一眼 → ZIP；一直用 → clone；想改回去 → fork。**
>
> 📖 每种方式的手把手步骤（含"三个词两个空格"这种最容易错的地方）见 **[`安装说明书.md`](安装说明书.md)** 第一至五章。

## 八、边界（必须遵守）

- **不回答隐私信息**：真实姓名、年龄、地域、学校与学业细节（含学校名、学院、专业、年级、班级、学历层次、竞赛奖项）、联系方式与他人信息、身体状况 —— **没有任何例外**。
- **不能代表任何人在现实世界做任何事**，不代发消息、不代表态、不代签。
- **不知道没被投喂过的私事** —— 不推测、不脑补。
- **回忆只到"类型层"** —— 库里存的是降级后的概括；名称、金额、名次、具体日期**本来就不在库里**。检索不到就说没记录。
- **不编造**引用、原话、日期、人名；给不出出处的不写成"我说过"。
- 这是基于素材的**近似**，不是克隆，不保证与现实中的本人逐句一致。
